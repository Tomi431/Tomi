Automating Weekly Product Research With Claude and MCP

Product research · 8 min read
← Back to all 7 playbooks

Every Monday you open 4 tools, run the same queries, compile the same spreadsheet. You have been doing this for years. What if your AI did it for you in 30 seconds?

That is the promise of connecting Claude to live marketplace data through MCP — the Model Context Protocol. Instead of logging into multiple dashboards, exporting CSV files, and stitching together a market picture by hand, you ask Claude one question and get a structured answer backed by real-time data. No switching tabs. No copy-paste. No pivot tables at 8 AM.

This article walks through how it works, what you can build with it, and how to set it up in under five minutes using the open-source sorftime-seller-agent MCP server.

The Weekly Research Routine, Deconstructed

Ask any marketplace seller what Monday morning looks like and the pattern is nearly identical across categories, revenue levels, and platforms. The player changes — Amazon, Walmart, TikTok Shop, Shopee — but the choreography does not.

Typical weekly research checklist:

1. Open the keyword tracker. Check which search terms shifted rank, which ones gained volume, which ones lost traction.

2. Open the competitor monitor. Scan for price changes, new listings, inventory signals, review velocity shifts.

3. Open the category dashboard. Look for new entrants, BSR movement, seasonal trend lines.

4. Open the profit calculator. Update cost inputs, check margin compression, flag SKUs that crossed below threshold.

5. Combine everything into a spreadsheet. Color-code the rows. Write a summary for the team.

Each step is 5 to 15 minutes of clicking through filters, date ranges, and export buttons. The cognitive load is not the analysis — the analysis takes 30 seconds once the data is in one place. The load is the assembly. Assembling data from fragmented tools is where the hours disappear.

What Happens When MCP Replaces the Assembly

MCP lets Claude talk directly to external data sources as if they were built-in functions. Instead of you reading a dashboard and telling Claude what you saw, Claude reads the data itself and answers your question.

Here is a concrete example. You type this prompt into Claude after connecting sorftime-seller-agent:

> "Check my tracked ASINs on Amazon US. Which competitors dropped price by more than 5 percent this week? Which keywords moved more than 10 positions? Flag any product with margin below 15 percent after fee changes. Output a table sorted by urgency."

Claude calls the relevant MCP tools — fetching product details, keyword rankings, fee estimates — combines the results, and returns a formatted table. Total time: roughly 30 seconds. The same analysis done manually: 45 minutes minimum, spread across three browser tabs and a spreadsheet.

The difference is not speed alone. It is that the bottleneck moves from data collection to decision-making. You stop being a human ETL pipeline and start being a strategist again.

What sorftime-seller-agent Provides

sorftime-seller-agent is an open-source MCP server that exposes marketplace intelligence as tools Claude can call. It covers over 130 endpoints across Amazon, Walmart, TikTok Shop, Shopee, Temu, and 1688.

Here is what Claude can do once the server is connected:

  • Read real-time product data: price, BSR, ratings, review count, inventory signals, buy box status.
  • Track keyword rankings across time periods and detect movement patterns.
  • Pull category-level data: bestseller lists, new releases, Movers and Shakers.
  • Calculate profit estimates with configurable cost inputs (COGS, FBA fees, referral fees, shipping).
  • Monitor competitor catalogs for new ASIN launches, price changes, and review velocity shifts.
  • Cross-reference data across platforms in a single query.

Each capability is a discrete tool in the MCP server. Claude decides which tools to call based on your question. You do not need to know the endpoint names or parameter formats — Claude handles that automatically.

Setting It Up

The setup is three steps and takes under five minutes. You need Python 3.10 or later and a Claude client that supports MCP (Claude Desktop, Claude Code, or any MCP-compatible client).

### Step 1: Clone and Install

git clone https://github.com/DannylydST/sorftime-seller-agent
cd sorftime-seller-agent
python3 scripts/install.py

The install script sets up a Python virtual environment, installs dependencies, and generates a starter configuration file.

### Step 2: Configure Your MCP Client

Add the server to your Claude client's MCP configuration. For Claude Desktop, edit claude_desktop_config.json:

{
  "mcpServers": {
    "sorftime-seller-agent": {
      "command": "python3",
      "args": ["-m", "sorftime_seller_agent"],
      "env": {
        "SORFTIME_API_KEY": "your-api-key-here"
      }
    }
  }
}

For Claude Code, add it to .claude/mcp.json in your project or home directory with the same structure.

### Step 3: Get an API Key

Sign up at open-intl.sorftime.com to get a free API key. The free tier includes enough quota to run weekly research workflows on a standard product portfolio.

Restart your Claude client. You should see a hammer icon or tool indicator confirming the MCP server is connected. Ask Claude: "List the tools you have access to." If sorftime-seller-agent tools appear, you are ready.

A Real Monday Morning Prompt

Once connected, here is a prompt you can use as a starting template. It covers the four core areas of a weekly review in a single query.

> "Run my weekly product health check. For all ASINs I am tracking:

>

> 1. Compare current BSR and price against last week. Flag changes over 10 percent.

> 2. Pull keyword rankings for my top 5 target terms per ASIN. Note any position shifts.

> 3. Check for new competitors that entered the top 20 BSR in each ASIN's primary category.

> 4. Recalculate profit margins using current FBA fee estimates and my standard COGS. Highlight anything below 18 percent.

>

> Format the output as a markdown table with one row per ASIN and a one-line verdict for each."

Claude executes this by calling the relevant tools in sequence, waiting for each result before making the next call, then synthesizing everything into a single structured table.

The first time you run it, review the output and refine the prompt — add your specific margin thresholds, your competitor watchlist, the keywords that matter to your category. By the third week, the prompt is dialed in and Monday morning research takes the time it takes to type "run my weekly product health check."

Why This Architecture Works

There is a deeper reason this approach is gaining traction among marketplace sellers. Traditional SaaS dashboards are designed for human data consumption — charts, tables, filters, export buttons. They optimize for a person looking at a screen and making decisions click by click.

MCP flips the model. Data flows directly into the reasoning engine. Claude does not need a chart. It needs structured numbers, and it is better at spotting patterns across multiple data dimensions than a human scanning a dashboard.

This also means your research scales without adding headcount. Tracking 10 ASINs or 100 ASINs is the same prompt. Claude handles the fan-out, calling tools for each ASIN and aggregating results. What changes is execution time, not your effort.

What This Does Not Do

A few honest boundaries. The MCP server provides data access and tool definitions. It does not make business decisions for you. It will not tell you which product to launch. It will not guarantee a keyword ranks or a margin holds. Market conditions shift, fees change, and data always has a freshness window.

The value is in removing the repetitive assembly work so you can spend your attention on the decisions that require judgment. Think of it as moving from "person who collects data" to "person who interprets data."
