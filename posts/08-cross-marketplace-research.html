Cross-Marketplace Product Research Without Switching Tools

Cross-marketplace research · 7 min read
← Back to all playbooks

Your product sells on Amazon. You're curious about Walmart. You've heard TikTok Shop is growing. But researching each platform means learning a new dashboard, new metrics, new workflows. What if one query gave you all three?

That is the problem sorftime-seller-agent solves. It is an open-source MCP (Model Context Protocol) server that connects AI agents to marketplace intelligence across six platforms. Instead of logging into separate dashboards, running manual exports, and stitching spreadsheets together, sellers can ask a single question and get structured data back — from wherever the data lives.

The Multi-Platform Problem

Most ecommerce sellers start on one marketplace. Amazon is the common entry point. But as a business grows, two things happen. First, the seller starts looking at other channels — Walmart for US reach, TikTok Shop for social commerce, Shopee for Southeast Asia, TEMU for price-sensitive buyers. Second, the seller discovers that cross-platform research is brittle.

Each platform has its own dashboard. Each dashboard has its own navigation logic, its own metric names, its own export formats. Comparing a product's performance across Amazon and Walmart means logging into both, pulling separate reports, manually aligning column headers, and hoping nothing was missed. For a seller managing dozens or hundreds of SKUs, this is hours of work per week.

Even within a single platform, the dashboard is opinionated about what data to show and how to show it. A seller who wants to answer a specific question — "which of my Amazon listings have the highest return rate relative to their price point" — often cannot answer it inside the dashboard at all. The data is there, but the interface was not designed for that query.

What MCP Changes

MCP, the Model Context Protocol, is an open standard for connecting AI agents to external data sources. Instead of an AI model answering from training data alone, an MCP server gives it structured access to live data through defined tools. The model can call a function like get_product_detail, receive a structured response, and reason about it.

sorftime-seller-agent is an MCP server built on top of Sorftime's data infrastructure. It exposes marketplace data as a set of tools that any MCP-compatible AI agent can call. The seller does not need to know which API endpoint returns which field. The seller asks a question, and the agent routes it to the right tool.

This matters because it inverts the research workflow. Instead of the seller adapting to each platform's interface, the interface adapts to the seller's question. A single query format works across marketplaces, and the agent handles the platform-specific details under the hood.

A Working Example

Consider a seller who wants to understand the competitive landscape for yoga mats. On a typical day, this seller would check Amazon Best Seller rankings in the yoga category, search Walmart for comparable listings, and browse TikTok Shop to see what styles are trending in short video content. Each step requires a different login, a different search interface, and a different export format.

With sorftime-seller-agent, the seller runs one MCP client — such as Claude Code, Cursor, or any terminal-based agent — and asks a natural language question. The agent calls the relevant tools across platforms, compiles the results, and presents a comparison.

The same query pattern works for Walmart, TikTok Shop, Shopee, TEMU, and 1688. The field names are consistent where they overlap. The agent handles the differences.

Here is a cross-platform price comparison script that can be run directly:

# Cross-platform price scan for a given product keyword
# Requires: sorftime-seller-agent installed and MCP config set

import subprocess
import json

keyword = "yoga mat"
platforms = ["amazon", "walmart", "shopee", "temu"]

results = {}

for platform in platforms:
    cmd = [
        "sorftime-cli", "search",
        "--platform", platform,
        "--keyword", keyword,
        "--marketplace", "US",
        "--sort", "relevance",
        "--limit", "10",
        "--fields", "title,price,rating,reviews,url"
    ]
    output = subprocess.run(cmd, capture_output=True, text=True)
    results[platform] = json.loads(output.stdout)

# Print comparison table
print(f"\n{'Platform':<12} {'Avg Price':>10} {'Max Price':>10} {'Min Price':>10} {'Listings':>10}")
print("-" * 55)
for platform, data in results.items():
    prices = [item["price"] for item in data.get("items", []) if item.get("price")]
    if prices:
        print(f"{platform:<12} {sum(prices)/len(prices):>10.2f} {max(prices):>10.2f} {min(prices):>10.2f} {len(prices):>10}")

This script can be dropped into a daily cron job. Every morning, the seller gets a fresh cross-platform price scan without opening a single dashboard.

Setup and Configuration

sorftime-seller-agent is distributed as a Python package. Installation takes one command. Configuration is a JSON file that specifies which platforms to enable and which API credentials to use. For sellers without existing Sorftime accounts, a free tier is available at open-intl.sorftime.com that covers Amazon US data with daily quotas sufficient for individual research.

The server connects to any MCP-compatible client. The most common setup is with Claude Code, which supports MCP natively. After installing the server, the seller adds a few lines to their Claude Code configuration, and the tools become available in every session. Other MCP clients like Cursor and VS Code extensions follow the same pattern.

Once configured, the seller can start a conversation with any MCP client and ask marketplace questions directly. No context switching. No dashboard hopping.

Why Open Source

sorftime-seller-agent is open source under the MIT license. The code is at github.com/DannylydST/sorftime-seller-agent. The tools are defined in plain Python, and the MCP protocol is fully documented. Sellers who want to extend the server — adding a platform that is not yet covered, or customizing the data fields returned by a tool — can fork the repository and build on top of the existing structure.

This is intentional. Marketplace data is not a secret sauce. The value comes from how sellers use it, and every seller has different questions. An open-source foundation means the community can add tools for niche platforms, build custom analysis pipelines, and share integrations. The core data infrastructure is maintained, but the surface area grows with the people who use it.

What sorftime-seller-agent Does Not Do

It does not replace the need to understand each marketplace. A Walmart listing strategy is different from an Amazon strategy, and data alone does not bridge that gap. It does not guarantee sales outcomes. It does not automate listing creation or inventory management. It is a research tool — it surfaces the data sellers need to make decisions, and then gets out of the way.

It also does not require sellers to abandon their existing workflows. If a seller already uses spreadsheets for tracking, the agent can output CSV. If a seller uses Notion or Airtable for product databases, the agent can format data for those systems. The agent is a data pipe, not a walled garden.
